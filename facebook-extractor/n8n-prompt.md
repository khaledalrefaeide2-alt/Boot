# برومبت n8n — بناء وورك فلو يؤدي وظيفة موقع «الإعلام الرقمي»

انسخ النص المحصور بين السطرين وألصقه في **n8n AI Workflow Builder** (أو أعطه لأي مساعد ذكي لبناء الـ workflow).

---

## البرومبت (انسخ من هنا)

```
ابنِ لي workflow في n8n لرصد وتحليل محتوى وسائل التواصل الاجتماعي وفق إطار الثقة والأمان
(Trust & Safety) السوري. الوورك فلو يجب أن يؤدي الوظائف التالية بالكامل:

═══════════════════════════════════════════
1) المُشغِّلات (Triggers)
═══════════════════════════════════════════
أنشئ ثلاثة مسارات دخول:
- Schedule Trigger: يعمل كل 30 دقيقة (اجعل الفترة قابلة للتعديل: 15/30/60 دقيقة).
- Webhook Trigger (POST): لتشغيل استخراج فوري يدوياً مع تمرير المعطيات في الـ body:
  { platform: "facebook" | "twitter", targets: [...], limit: 20, from: "YYYY-MM-DD", to: "YYYY-MM-DD" }
- Manual Trigger: للتجريب.

═══════════════════════════════════════════
2) الاستخراج من فيسبوك عبر Apify
═══════════════════════════════════════════
استخدم HTTP Request nodes على واجهة Apify REST API، مع تخزين التوكن في n8n Credentials
(Header Auth أو Environment Variable) وليس داخل العُقد نصّاً صريحاً.

الخطوة أ — بدء التشغيل:
  POST https://api.apify.com/v2/acts/apify~facebook-posts-scraper/runs?token={{$env.APIFY_TOKEN}}&maxItems={{ $json.limit * $json.targets.length }}
  Body (JSON):
  {
    "startUrls": [ { "url": "https://www.facebook.com/PAGE_NAME" } ],
    "resultsLimit": 20,
    "onlyPostsNewerThan": "2025-01-01",   // اختياري
    "onlyPostsOlderThan": "2025-12-31"    // اختياري
  }
  مهم: معامل maxItems في الـ URL هو سقف الفوترة الإلزامي — يوقف التشغيل ولا يُحاسب على
  أكثر منه، بخلاف resultsLimit الذي يبقى تقريبياً فقط.

الخطوة ب — الانتظار حتى الانتهاء:
  استخدم Wait node (4 ثوانٍ) داخل حلقة مع
  GET https://api.apify.com/v2/actor-runs/{{ $json.data.id }}?token={{$env.APIFY_TOKEN}}
  وكرّر ما دامت الحالة READY أو RUNNING. اعتبر SUCCEEDED نجاحاً، وكذلك
  ABORTED إذا كان الـ dataset يحوي عناصر (لأن بلوغ سقف maxItems يوقف التشغيل ذاتياً).
  أضف سقفاً زمنياً أقصى (مثلاً 10 دقائق) لتفادي الحلقات اللانهائية.

الخطوة ج — جلب النتائج:
  GET https://api.apify.com/v2/datasets/{{ defaultDatasetId }}/items?clean=true&format=json&token={{$env.APIFY_TOKEN}}

═══════════════════════════════════════════
3) الاستخراج من منصة X (تويتر) عبر Apify
═══════════════════════════════════════════
نفس المنطق تماماً لكن بمُشغِّل (actor) مختلف ومدخلات مختلفة:
  POST https://api.apify.com/v2/acts/pzMmk1t7AZ8OKJhfU/runs?token={{$env.APIFY_TOKEN}}&maxItems=N
  Body (JSON):
  {
    "query": "from:user1 OR from:user2",
    "mode": "Advanced Search",
    "query_type": "Latest",
    "max_results": 40
  }
  ابنِ حقل query بدمج أسماء المستخدمين على الشكل from:HANDLE مفصولة بـ " OR ".
  تحقّق أن كل handle يطابق ^[A-Za-z0-9_]{1,15}$ قبل الإرسال.

═══════════════════════════════════════════
4) التوحيد (Normalization) — Code node
═══════════════════════════════════════════
حوّل كل عنصر خام إلى الشكل الموحّد التالي، مع دعم تعدد أسماء الحقول:
{
  text:     raw.text || raw.message || raw.postText || raw.full_text,
  url:      raw.url || raw.postUrl || raw.topLevelUrl,
  ts:       طابع زمني بالمللي ثانية من raw.time/date/publishedTime/timestamp
            (اضرب ×1000 إذا كانت القيمة أصغر من 1e12),
  author:   raw.user?.name || raw.pageName || raw.author,
  avatar:   raw.user?.profilePic || raw.pageProfilePic,
  likes:    raw.likes ?? raw.likesCount ?? raw.reactions ?? raw.favorite_count,
  comments: raw.comments ?? raw.commentsCount ?? raw.reply_count,
  shares:   raw.shares ?? raw.sharesCount ?? raw.retweet_count,
  views:    raw.viewsCount ?? raw.videoViewCount ?? raw.views,
  postId:   raw.postId || raw.id || raw.post_id,
  media:    استخرج الصور والفيديوهات من raw.media/attachments/images/photos/videos,
  platform: "facebook" | "twitter"
}
حوّل الأرقام النصية ("1.2K") إلى أعداد صحيحة، واستبعد أي عنصر بلا text وبلا url.

═══════════════════════════════════════════
5) محرك التصنيف — Code node (الجزء الأهم)
═══════════════════════════════════════════
لكل منشور، طبّق تحليلاً تسلسلياً (Chain of Thought) يُخرج:
  التصنيف النهائي (إيجابي/سلبي/حيادي) ← مستوى الخطورة أو الأهمية (منخفض/متوسط/عالي)
  ← تحليل سياقي يشرح السبب ← استناد قانوني وأخلاقي دقيق ← إجراء موصى به
  (الإبقاء / الحذف الفوري / التحويل للمراجعة البشرية).

أولاً — تطبيع النص العربي قبل أي مطابقة:
  احذف التشكيل والتطويل، وحوّل (إ أ آ ا)→ا ، ى→ي ، ؤ→و ، ئ→ي ، ة→ه ،
  ووحّد المسافات وحوّل لأحرف صغيرة.

ثانياً — الفئات السلبية (كل فئة لها مستوى خطورة وإجراء واستناد قانوني):

| الفئة | الخطورة | الإجراء | الاستناد |
|---|---|---|---|
| الدعوة لتغيير الدستور بطرق غير مشروعة / عصيان مسلح / سلخ أرض | عالي | حذف فوري | المادة 27 من قانون الجرائم المعلوماتية 20/2022 |
| النيل من هيبة الدولة والمساس بالوحدة الوطنية | عالي | حذف فوري | المادة 28 |
| زعزعة الثقة بالعملة الوطنية وأسعار الصرف | عالي | حذف فوري | المادة 29 |
| خطاب الكراهية والتمييز (ديني/قومي/عرقي/لغوي/جندري) | عالي | حذف فوري | سياسات Meta وX + مدونة السلوك الإعلامي + المادة 33 كظرف مشدد |
| الإساءة للرموز والمقدسات والشعائر الدينية | عالي | حذف فوري | المادة 31 |
| استغلال الفئات الهشة (أطفال/نساء/ذوي إعاقة/فقراء) | عالي | حذف فوري | المادة 26 + المادة 33/ب |
| الترويج للمخدرات والمؤثرات العقلية | عالي | حذف فوري | المادة 30 |
| محتوى منافٍ للحشمة أو الحياء العام / ابتزاز | عالي | حذف فوري | المادة 26 |
| القدح والذم والتحقير الإلكتروني | متوسط | مراجعة بشرية | المادتان 24 و25 |
| انتهاك الخصوصية (نشر معلومات/صور/تسجيلات خاصة) | متوسط | مراجعة بشرية | المادتان 21 و23 |
| الأخبار الكاذبة والشائعات غير الموثّقة | متوسط | مراجعة بشرية | مدونة السلوك الإعلامي (وترتقي للمادة 28 عند استهداف الدولة) |

ثالثاً — الفئات الإيجابية (الإجراء دائماً: الإبقاء):
- تعزيز السلم الأهلي والعدالة الانتقالية ونبذ الانتقام — أهمية عالية.
- دعم حقوق الإنسان والتنوع الثقافي وتمكين الفئات الهشة — أهمية عالية.
- مكافحة التضليل بنشر حقائق موثّقة تدحض الشائعات — أهمية متوسطة.
- التوعية بالأمان الرقمي والتحذير من الجرائم الإلكترونية — أهمية متوسطة.
- دعم بناء الدولة ومؤسساتها وإعادة الإعمار وسيادة القانون — أهمية متوسطة.

رابعاً — الحالات الخاصة (يجب تطبيقها قبل إصدار الحكم النهائي، فهي جوهر دقة النظام):
1. نقل الانتهاك بقصد الإدانة والتوثيق (وجود «ندين»، «نستنكر»، «للتحذير من»،
   «هذا خطاب كراهية مرفوض») ← يُصنَّف إيجابياً (توعية) لا سلبياً، مع وسم
   «استثناء توثيق/إدانة».
2. سخرية سياسية عامة لا تستهدف شخصاً بعينه ولا تستهزئ بضحايا ← حيادي، خطورة منخفضة،
   الإبقاء (حرية رأي مشروعة).
3. القدح بحق شخصية عامة أو مسؤول (وزير/رئيس/محافظ/نائب/الحكومة) ← تشديد المستوى
   إلى عالي والإجراء إلى حذف فوري (المادتان 24 و25 تشدّدان العقوبة على المكلَّف بعمل عام).
4. اتهام بلا أي دليل (افتراء) ← ينتقل من النقد المشروع إلى القدح ← عالي + حذف.
5. سخرية تستهدف أعراض الناس أو مآسي الضحايا ← قدح وتحقير (سلبي).
6. النقد البنّاء لسياسة عامة («نقترح»، «نطالب بإصلاح»، «يجب تحسين») ← حيادي مشروع، الإبقاء.
7. نص استفهامي بحت ← حيادي، خطورة منخفضة.
8. خبر إحصائي/تقرير مجرد بأرقام ونسب ← حيادي، أهمية متوسطة.

خامساً — عند تطابق عدة فئات سلبية: رتّبها حسب الخطورة (عالي ← متوسط ← منخفض) ثم حسب
عدد المطابقات، واعتمد الأعلى كتصنيف رئيسي، مع ذكر الفئات الأخرى في التحليل السياقي.

سادساً — تحليل المصدر لكل منشور:
احسب مجموع التفاعل (إعجابات + تعليقات + مشاركات) وصنّف المصداقية:
  ≥5000 «حساب واسع الانتشار — تأثيره مرتفع» · ≥500 «متوسط التأثير» ·
  >0 «محدود التفاعل» · 0 «تفاعل غير معروف/منخفض».
واستنتج نوع الحساب: إن احتوى الاسم على news/media/official/gov/رسمي/اخبار/قناة/وكالة
فهو «صفحة إعلامية/رسمية (مرجّح)»، وإلا «صفحة/حساب عام».

ملاحظة: يمكن اعتماد أحد نهجين للتصنيف — إما Code node بقوائم كلمات مفتاحية لكل فئة
(سريع، بلا تكلفة، حتمي النتائج)، أو عقدة AI Agent / Basic LLM Chain بنموذج لغوي
يُمرَّر له الإطار أعلاه كـ system prompt ويُلزَم بإخراج JSON منظَّم عبر Structured
Output Parser. الأفضل عملياً: دمج الاثنين — الكلمات المفتاحية كمرشّح أولي سريع، ثم
عرض الحالات المشكوك فيها فقط على النموذج اللغوي لضبط الحالات الخاصة الثماني أعلاه.

═══════════════════════════════════════════
6) منع التكرار والتخزين
═══════════════════════════════════════════
- ولّد مفتاحاً فريداً لكل منشور من رابطه (أو postId عند غياب الرابط).
- قبل الحفظ، افحص وجود المفتاح مسبقاً (Postgres/MySQL/Supabase/Google Sheets/Airtable —
  اختر ما هو متاح، ويُفضَّل Postgres). إن كان موجوداً: حدِّث أرقام التفاعل فقط
  (likes/comments/shares/views) ولا تُنشئ صفاً جديداً — استخدم UPSERT
  (ON CONFLICT (key) DO UPDATE).
- بنية الجدول المقترحة:
  key (PRIMARY KEY), text, url, ts, author, avatar, media, likes, comments, shares,
  platform, classification, level, sub_category, legal_basis, contextual_analysis,
  action, flagged, analysis_json, saved_at
- أضف فهرساً على ts تنازلياً لتسريع الاستعلامات.

═══════════════════════════════════════════
7) التنبيهات والمخرجات
═══════════════════════════════════════════
- IF node: إذا كان الإجراء = «الحذف الفوري» أو الخطورة = «عالي»، أرسل تنبيهاً فورياً
  عبر Slack/Telegram/Email يتضمن: المنشور، الرابط، التصنيف، الفئة، الاستناد القانوني،
  والإجراء الموصى به.
- تقرير دوري (Schedule يومي): جمّع إحصائيات اليوم (الإجمالي، إيجابي/سلبي/حيادي،
  عالي/متوسط/منخفض، عدد ما يحتاج حذفاً، عدد ما يحتاج مراجعة) وأرسلها كملخص.
- تصدير: عقدة Convert to File لإنتاج CSV/XLSX من نتائج الفترة، مع دعم العربية
  (ترميز UTF-8 مع BOM).

═══════════════════════════════════════════
8) متطلبات عامة
═══════════════════════════════════════════
- ضع كل المفاتيح في n8n Credentials أو متغيرات البيئة — لا تكتب أي توكن داخل العُقد.
- أضف Error Trigger / Error Workflow لالتقاط فشل أي تشغيل والتنبيه عليه.
- فعّل إعادة المحاولة (Retry On Fail) على عقد HTTP بفاصل تصاعدي.
- احترم سقف maxItems دائماً لضبط التكلفة.
- سمِّ كل عقدة باسم عربي واضح يصف وظيفتها، ورتّب الوورك فلو في مسارين متوازيين
  (فيسبوك / X) يلتقيان عند عقدة التوحيد ثم التصنيف ثم التخزين.
```

## ملاحظات تنفيذية

| النقطة | التفصيل |
|---|---|
| **مُشغِّل فيسبوك** | `apify~facebook-posts-scraper` |
| **مُشغِّل X** | `pzMmk1t7AZ8OKJhfU` (حقل `mode` يقبل `"Advanced Search"` حصراً) |
| **سقف التكلفة** | `maxItems` في الـ URL هو الملزِم فعلياً، لا `resultsLimit` |
| **الفارق عن الموقع** | الموقع يعمل محلياً في المتصفح دون إرسال بيانات لأي خادم؛ في n8n تمرّ البيانات عبر خادم n8n — إن كانت السرّية شرطاً، استضِف n8n ذاتياً (self-hosted) |
| **دقة التصنيف** | الحالات الخاصة الثماني هي ما يميّز النظام عن مجرد بحث عن ألفاظ مسيئة — لا تحذفها عند الاختصار |
