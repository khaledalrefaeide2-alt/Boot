# النشر على Render

> ملف المواصفة [`render.yaml`](../render.yaml) في **جذر المستودع** لا في هذا
> المجلد — Render يبحث عنه هناك وحده.

---

## سبب فشل أول نشر

```
==> Running 'npm run start:prod'
npm error code ENOENT
npm error path /opt/render/project/src/package.json
npm error enoent Could not read package.json
```

`/opt/render/project/src` هو جذر المستودع كما يراه Render. و`package.json`
ليس هناك — هو في **`platform/`**:

```
Boot/                    ← جذر المستودع = /opt/render/project/src
├── main.js
├── src/
├── facebook-extractor/
└── platform/            ← ★ package.json هنا
```

فبحث npm في الجذر ولم يجد شيئاً، وخرج بالرمز 254. الأمر نفسه سليم — الخطأ في
**مكان تنفيذه**.

### الحلّ — سطر واحد في الإعدادات

**Settings ← Build & Deploy ← Root Directory** → اكتب:

```
platform
```

ثم **Manual Deploy ← Deploy latest commit**.

هذا وحده يُصلح الخطأ الظاهر في السجل.

## قيود خطة Render التي تمسّ هذه المنصة

اقرأها قبل أن تكمل — بعضها يظهر أثره بعد النشر لا أثناءه:

| القيد | الأثر على المنصة |
|---|---|
| **Background Worker لا خطة مجانية له** | بدونه يفتح الموقع ويعرض البيانات، لكن **كل ضغطة «استخراج» لا تُنفَّذ** — تبقى في الطابور بلا من يسحبها |
| **PostgreSQL المجانية تنتهي بعد 30 يوماً** | تُحذف القاعدة وبياناتها. للاستعمال الحقيقي تلزم خطة مدفوعة |
| **Key Value المجانية بلا استمرارية** | إعادة تشغيل الخدمة تُفرغ الطابور |
| **الخدمة المجانية تنام بعد خمول** | أول طلب بعد النوم يتأخر عشرات الثواني |

**الخلاصة:** الموقع يعمل على المجاني للتجربة، لكن **الاستخراج — وهو وظيفة
المنصة — يحتاج عاملاً خلفياً مدفوعاً.**

---

## عائق ثانٍ كان سيظهر بعد إصلاح المسار — وقد أُصلح

Render يضبط `NODE_ENV=production` لخدمات Node، وعندها **يتخطّى npm تثبيت
`devDependencies`**. مُختبَر: التثبيت ينزل من 358 حزمة إلى 331، و**`tsx`
يختفي**.

وهذا كان سيكسر أمرين بعد أن يعمل الموقع:

| الأمر | يحتاج | النتيجة قبل الإصلاح |
|---|---|---|
| `npm run worker:prod` | `tsx` | ✗ لا يقلع أصلاً |
| `npm run deploy:bootstrap` | `tsx` للبذر | ✗ يفشل بعد الترحيل |
| `npm run start:prod` | `next` فقط | ✓ يعمل |

فالعطل كان سيبدو أن «الموقع يعمل لكن الاستخراج لا ينفّذ» — وهو أصعب ما
يُشخَّص.

**الإصلاح:** نُقل `tsx` و`prisma` من `devDependencies` إلى `dependencies`،
لأنهما **فعلاً** اعتماديتا تشغيل في الإنتاج لا أدوات تطوير: العامل والبذر
يمرّان بـ `tsx`، والترحيلات تمرّ بـ `prisma`. (مُختبَر بعد النقل: تثبيت
إنتاجي كامل يُبقي الثلاثة.)

هذا يجعل **مسار Node runtime صالحاً أيضاً**، لا Docker وحده.

## الطريق الموصى به: Docker

المشروع يحمل `Dockerfile` مجرَّباً وثلاثة أوامر تشغيل جاهزة، وصورة واحدة
تخدم الويب والعامل والترحيلات. وهو أقرب إلى ما جُرِّب فعلاً.

### إعداد خدمة الويب

| الحقل | القيمة |
|---|---|
| Language / Runtime | **Docker** |
| **Root Directory** | **`platform`** ← السطر الذي كان ينقص |
| Dockerfile Path | `./Dockerfile` |
| Docker Command | `npm run start:prod` |
| Health Check Path | `/api/health` |
| Instance Type | Starter فأعلى |

### إعداد العامل الخلفي (Background Worker)

| الحقل | القيمة |
|---|---|
| Language / Runtime | **Docker** |
| **Root Directory** | **`platform`** |
| Dockerfile Path | `./Dockerfile` |
| Docker Command | `npm run worker:prod` |
| Instances | **1 — ولا تزده** |

> الجدولة الدورية مؤقّت داخل العملية لا مهمة طابور. كل نسخة إضافية تُعيد
> جدولة الحسابات المستحقة كل دقيقة بشكل مستقل، فتتكرر عمليات الاستخراج
> وتُستهلك حصة Apify مرتين.

### الترحيلات

Render يوفّر **Pre-Deploy Command** على الخطط المدفوعة:

```
npm run deploy:bootstrap     ← أول نشر (ترحيل + بذر، يفشل صراحةً عند الخطأ)
npm run deploy:migrate       ← بعده (ترحيل فقط)
```

**إن لم تتوفر لديك** (خطة مجانية): شغّلها مرة واحدة من **Shell** في لوحة
الخدمة بعد أول نشر:

```bash
npm run deploy:bootstrap
```

> لا تترك الموقع يعمل على قاعدة بلا جداول — كل صفحة ستعطي خطأ.

## متغيرات البيئة

| المتغيّر | web | worker | المصدر |
|---|:--:|:--:|---|
| `DATABASE_URL` | ✅ | ✅ | من قاعدة Render (Internal Connection String) |
| `REDIS_URL` | ✅ | ✅ | من Key Value (Internal) |
| `SESSION_SECRET` | ✅ | ✅ | `openssl rand -base64 48` — **القيمة نفسها في الاثنين** |
| `APP_URL` | ✅ | — | رابط الخدمة: `https://<اسم-الخدمة>.onrender.com` |
| `APIFY_TOKEN` | ✅ | ✅ | console.apify.com |
| `NODE_ENV` | ✅ | ✅ | `production` |
| `DATABASE_CA_CERT` | ⚪ | ⚪ | انظر أدناه |
| `WORKER_CONCURRENCY` | — | ⚪ | اختياري (2) |

**`APP_URL` ليس اختيارياً.** بدونه يبقى الافتراضي `http://localhost:3000`،
وفحص مصدر الطلب يرفض **كل** محاولة تسجيل دخول من الرابط الحقيقي.

**`PORT` لا تضبطه.** Render يحقنه، والمشغّل يقرأه تلقائياً. وترتيب الأولوية
`APP_PORT` ← `PORT` ← `3000`، فضبط `APP_PORT` هنا يُبطل ما يحقنه Render.

### عن `DATABASE_CA_CERT`

الاتصال بقاعدة Render من **داخل شبكة Render** (Internal Connection String)
لا يمرّ بالإنترنت. أما الاتصال الخارجي فيفرض TLS.

- استعمل **Internal Connection String** دائماً بين الخدمات — وعندها غالباً
  لا تحتاج الشهادة.
- إن ظهر خطأ شهادة عند الاتصال، نزّل شهادة السلطة من لوحة القاعدة وضعها في
  `DATABASE_CA_CERT`. تُقبل بصيغة PEM كاملة أو مُرمّزة بـ base64.

> **غير مؤكد:** لم أختبر الاتصال بقاعدة Render — لم أنشئ أي مورد. آلية
> التحقق نفسها مفحوصة (`npm run verify:db-ssl`)، لكن ما إذا كانت قاعدة Render
> الداخلية تطلب شهادة أم لا يحتاج تجربة عندك.

## الخطوات

**١)** أنشئ **PostgreSQL** و**Key Value** من لوحة Render. اضبط سياسة الإخلاء
على `noeviction` في الثانية.

**٢)** أنشئ **Web Service** من المستودع، بالإعدادات أعلاه — وأهمّها
**Root Directory = `platform`**.

**٣)** اضبط متغيرات البيئة. اترك `APP_URL` مؤقتاً ثم املأه بعد أن يعطيك
Render الرابط.

**٤)** انشر، ثم شغّل التهيئة (Pre-Deploy أو Shell):

```bash
npm run deploy:bootstrap
```

**٥)** تحقّق:

```
https://<خدمتك>.onrender.com/api/health   →   200  {"ok":true}
```

**٦)** أنشئ **Background Worker** بالإعدادات أعلاه — **بخطة مدفوعة**.

**٧)** ادخل الموقع، ثم **لوحة الإدارة ← الإعدادات**: تأكّد أن Apify متصل وأن
الطابور «متصل والعامل الخلفي يسحب المهام».

**٨)** غيّر كلمة مرور المالك، وفرّغ `SEED_OWNER_PASSWORD`، وغيّر أمر التهيئة
إلى `npm run deploy:migrate`.

## أعطال Render الشائعة

| العَرَض | السبب | الحل |
|---|---|---|
| `ENOENT ... /opt/render/project/src/package.json` | Root Directory غير مضبوط | اضبطه على `platform` |
| `Exited with status 254` | نتيجة الخطأ أعلاه | نفسه |
| الموقع يفتح لكن كل صفحة تعطي خطأ | الجداول غير منشأة | `npm run deploy:bootstrap` من Shell |
| تسجيل الدخول يُرفض دائماً | `APP_URL` غير مضبوط أو لا يطابق الرابط | اضبطه على رابط `.onrender.com` |
| «استخراج» لا ينفّذ شيئاً | لا عامل خلفي يعمل | أنشئ Background Worker (مدفوع) |
| «الطابور متوقف» | `REDIS_URL` غير مضبوط أو Key Value متوقف | راجع الربط |
| أول طلب بطيء جداً | الخدمة المجانية تنام | خطة مدفوعة |

## ما لم يُختبَر

| البند | الحالة |
|---|---|
| النشر على Render | **لم يُنفَّذ** — لم تُنشأ أي موارد |
| بناء صورة Docker | **لم يُختبَر** — سحب الصور من Docker Hub محجوب في بيئة التطوير. اختُبر بدلاً منه تسلسل مراحل Dockerfile على نسخة نظيفة، ونجح |
| حقول `render.yaml` | **غير مؤكدة** — توثيق Render محجوب من بيئة التطوير. راجعها عند الاستيراد؛ الخطأ عندها يسمّي الحقل |
| الاتصال بقاعدة Render | **لم يُختبَر** |

**ما اختُبر فعلاً:** أوامر التشغيل الأربعة، وقراءة `PORT` مع الاستماع على
`0.0.0.0`، وفحص الصحّة في الاتجاهين، وإعداد TLS للقاعدة (20 فحصاً)، والبناء
من نسخة نظيفة.
