# التحليل الآلي للمنشورات

تحليل كل منشور بالذكاء الاصطناعي على ثلاثة أبعاد مستقلّة، مع تعليل ودرجة
ثقة يُعرضان دائماً بجانب النتيجة.

---

## الأبعاد الثلاثة

### 1. الموقف من سياسات الدولة — `stance`

| القيمة | المعنى |
|---|---|
| `SUPPORTIVE` | يدعم سياسات الدولة أو استقرارها أو مشاريع التنمية أو حقوق الإنسان والسلم الأهلي |
| `OPPOSED` | يعارض سياسات الدولة أو ينتقدها |
| `NEUTRAL` | خبري أو وصفي بلا موقف |
| `MIXED` | يؤيّد جانباً ويعارض آخر |
| `UNCLEAR` | غامض أو قصير فلا يمكن تحديده |

### 2. المشاعر — `sentiment`

نبرة النصّ وحدها، **مستقلّة عن الموقف**.

والفصل بينهما مقصود: منشورٌ غاضب النبرة قد يكون مؤيّداً (غضبٌ على معرقلي
مشروع)، وهادئٌ قد يكون معارضاً. وخلطهما في حقل واحد يُنتج رقماً لا يقرأ
أيّاً منهما.

### 3. إشارات المحتوى الضارّ — `riskFlags`

`INCITEMENT_VIOLENCE` · `SECTARIAN_REGIONAL` · `HATE_SPEECH` · `THREAT` ·
`PLATFORM_POLICY`

مع درجة `riskSeverity` من `NONE` إلى `HIGH`.

---

## ما لا يفعله هذا النظام — وسبب ذلك

**لا يُصدر حكماً قانونياً.** لا يوجد في مخرجاته تصنيف يقول إن منشوراً
يخالف قانوناً بعينه.

والسبب هندسي قبل أن يكون غيره: النموذج اللغوي يُنتج ترجيحاً احتمالياً،
والتكييف القانوني يحتاج وقائع وسياقاً ونيّةً وإجراءً. وبطاقةٌ آلية تقول
«هذا المنشور جريمة» مُعلَّقة على حساب باسم صاحبه تحمل تبعات لا يحتملها خطأ
تصنيف — وكلّ مصنّف يخطئ.

فالمخرجات **تصف النصّ** (فيه تحريض صريح، فيه لفظ طائفي)، والقرار — قانونياً
كان أو إدارياً — يبقى لإنسان يقرأ التعليل والثقة معاً من شاشة المراجعة.

**والنقد السياسي ليس محتوى ضارّاً.** الدليل ينصّ على ذلك صراحةً مرّتين:
معارضة الحكومة أو انتقاد مسؤول أو المطالبة بمحاسبة تُصنَّف `OPPOSED` ولا
تُرفع لها أي إشارة خطر. من دون هذه القاعدة يتحوّل المصنّف من أداة قياس رأي
إلى أداة وسم للمعارضين — وهما استعمالان مختلفان تماماً لنفس الشيفرة.

---

## ثلاثة ضمانات مبنيّة في النظام

1. **لا إجراء آلي.** التحليل لا يُخفي منشوراً ولا يغيّر تصنيفه اليدوي ولا
   يمسّ أي حقل يؤثّر على ظهوره. يكتب في جدول مستقل ويحدّث حقل المشاعر
   فقط — وحتى ذلك لا يكتب فوق تصنيف وضعه إنسان (`sentimentSource=MANUAL`).

2. **كل نتيجة موسومة ومؤرّخة.** يُحفظ اسم النموذج وتاريخ التحليل، فيُعرف
   دائماً من قال ماذا ومتى. وتغيير الدليل يستوجب إعادة التحليل، وإلا اجتمع
   في القاعدة تصنيفان بمعيارين.

3. **الثقة المنخفضة تُرفع للمراجعة.** كل نتيجة دون 0.6 ثقة، أو تحمل أي
   إشارة خطر، تُعلَّم `needsReview` وتظهر في `/admin/review`.

## التشغيل

```bash
# تحليل غير المحلَّل
./deploy/dc.sh exec app npm run analyze:posts

# آخر 7 أيام
./deploy/dc.sh exec app npm run analyze:posts -- --days 7

# سقف لهذه الجولة
./deploy/dc.sh exec app npm run analyze:posts -- --limit 200

# إعادة تحليل الكلّ (بعد تغيير الدليل)
./deploy/dc.sh exec app npm run analyze:posts -- --all
```

ومن الواجهة: صفحة المنشور فيها زرّ **«حلّل الآن»** لمن يملك صلاحية
`posts.classify`.

---

## تعديل معايير التصنيف

الدليل مكتوب نصّاً واحداً في:

```
src/lib/analysis/ai-analyzer.ts  →  ANALYSIS_RUBRIC
```

عدّله هناك، ثمّ **أعد تحليل ما سبق** (`--all`) — وإلا صار في القاعدة
تصنيفان بمعيارين مختلفين، ولا شيء في البيانات يدلّ على أيّهما أيّ.

---

## التكلفة

`gpt-4o-mini` بحرارة صفر، ومنشور واحد لكل طلب. التكلفة تُقاس بأجزاء من
السنت للمنشور. والحرارة صفر مقصودة: التصنيف قرارٌ يجب أن يتكرّر على النصّ
نفسه لا أن يتنوّع.
