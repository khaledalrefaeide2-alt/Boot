# تنظيف الردود المخزّنة سابقاً

استخراج إكس صار يجلب التغريدات وحدها: النطاق يُمرَّر بـ `-filter:replies` إلى
محرّك البحث نفسه، والاستيراد يُسقط ما يمرّ منها رغم ذلك، والعدّاد «ردود
مستبعَدة» يُظهر كم أُسقط في كل عملية.

لكن ذلك كلّه يمنع الجديد ولا يمسّ القديم. الردود التي دخلت القاعدة قبل هذا
الإصلاح باقية فيها، وهذا السكربت لها وحدها.

```bash
./deploy/dc.sh exec app npm run cleanup:replies
```

## لماذا يعرض قبل أن يحذف

الردود القديمة حُفظت قبل أن يوجد كشف الردّ، فلم يُحفظ معها ما يُثبت أنها ردود:
حقول المزوّد الصريحة (`isReply`، `inReplyToUsername`) لم تكن تُقرأ أصلاً، والعمود
`rawData` الذي كان سيحفظ العنصر الخام لا يكتبه الاستيراد.

فلم يبقَ إلا نصّ المنشور دليلاً، وهو دليل **ظنّي**: إكس يُصدّر الردّ بمنشنات من
رُدّ عليهم في أوّله، لكن تغريدةً أصليةً تخاطب جهةً تبدأ بالشكل نفسه تماماً —
«@moi_sy شكراً على الاستجابة» قد تكون ردّاً وقد تكون تغريدة مستقلّة.

ولذلك:

- **الافتراض عرضٌ لا حذف.** بلا `--confirm` لا يُمسّ شيء.
- **يُعرض ما سيُحذف** — توزّعه على الحسابات، وعيّنة من نصوصه وروابطه وسبب
  الحكم على كلٍّ منها.
- **درجة الحكم تُعلَن**: `قاطع` حين تُوجد حقول المزوّد المحفوظة، و`ظنّي` حين
  يكون النصّ هو الدليل الوحيد.

## ما لا يُحذف

- **السلاسل الذاتية.** الجزء الثاني من بيانٍ يكتبه الحساب تتمّةً لتغريدته ليس
  ردّاً على أحد. يُعرف بأن كلّ منشن متصدّر هو معرّف الحساب نفسه — وهو المعيار
  ذاته الذي يستعمله الاستيراد ليُبقيها.
- **إعادة التغريدة** (`RT @fulan:`) — إعادة نشر لا ردّ.
- **المنشن في وسط النصّ.** «شكراً لـ @fulan» كلامٌ عن أحد لا مخاطبةٌ له.
- **ما ينفيه المزوّد صراحةً.** إن كان `rawData` محفوظاً وفيه `isReply: false`
  فهو الحاكم، ولو بدأ النصّ بمنشن.

## الخيارات

| الخيار | ماذا يفعل |
| --- | --- |
| *(بلا خيارات)* | عرضٌ فقط — لا يُنفَّذ شيء |
| `--confirm` | التنفيذ الفعلي |
| `--hide` | إخفاء بدل حذف — قابل للتراجع من شاشة المنشورات |
| `--limit 50` | يقف عند أوّل ٥٠ مرشّحاً — لجولة أولى حذرة |
| `--account <id>` | حساب واحد بدل المنصة كلها |
| `--platform <code>` | منصة غير `x` |
| `--only-certain` | الأحكام القاطعة وحدها — يتجاهل ما دليله النصّ |
| `--sample 30` | كم عيّنةً تُعرض (الافتراضي ١٢) |

## الترتيب الموصى به

```bash
# ١) انظر ماذا يوجد — لا يحذف شيئاً
./deploy/dc.sh exec app npm run cleanup:replies

# ٢) جولة حذرة على حساب واحد، إخفاءً لا حذفاً
./deploy/dc.sh exec app npm run cleanup:replies -- --account <id> --limit 50 --hide --confirm

# ٣) راجع شاشة المنشورات، فإن صحّ الحكم فالحذف الكامل
./deploy/dc.sh exec app npm run cleanup:replies -- --confirm
```

## بعد الحذف

يُعيد السكربت حساب الإحصاءات اليومية لأيام ما حُذف وحدها. جداول
`DailyAccountStat` و`DailyPlatformStat` محسوبة مسبقاً، فحذف المنشور لا يُنقصها
من تلقاء نفسه، وتركها يعني لوحاتٍ تعدّ ما لم يعد موجوداً.

والحذف نهائي: المنشور وتحليله وتضمينه وارتباطاته بالكلمات المفتاحية تذهب معه
(`onDelete: Cascade`). من أراد رجعةً فليستعمل `--hide`.
