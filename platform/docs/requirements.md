## 1. النطاق

### 1.1 داخل النطاق

سلام منصة عامة تقوم على أربع ركائز:

1. **استخراج دوري** لمواد التحقق المنشورة من جهات تحقق عربية عبر Apify.
2. **مراجعة بشرية إلزامية** لكل عنصر مستخرج قبل أي ظهور عام.
3. **موقع عام** للتصفح والبحث وقراءة مواد التحقق، مع نظام أحكام ثابت.
4. **مساعد تحقق ذكي** يجيب اعتماداً على أدلة مسترجعة فقط.

### 1.2 خارج النطاق صراحةً

ذكر ما هو خارج النطاق جزء من المتطلبات، لا إغفال فيه:

| خارج النطاق | السبب |
|---|---|
| النشر التلقائي بأي درجة ثقة | يخالف المبدأ الأول للمنصة |
| تعليقات الجمهور على المواد المنشورة | سطح إساءة وإشراف لا يخدم مهمة التحقق |
| استخراج تعليقات المستخدمين من المصادر | خصوصية — يُستخرج المنشور لا المعلّقون عليه |
| إعادة نشر المادة الكاملة للمصدر | حوكمة محتوى — مقتطف وملخص ورابط فقط |
| تطبيق جوال أصلي | الويب المتجاوب يغطي الحاجة |
| واجهة بغير العربية | العربية أولاً؛ التدويل لاحق ولا يُعاد بناء الواجهة له |
| ادعاء بحث شامل للإنترنت | النتيجة تعتمد على المصادر المتاحة وقت التحقق، ويُصرَّح بذلك |
| تحليل المشاعر في المواد العامة | ميزة رصد داخلي، ليست منتجاً عاماً |

### 1.3 علاقة سلام بالمنصة القائمة

سلام **واجهة عامة تُضاف فوق النظام القائم**، لا بديل عنه ولا مشروع منفصل.
نظام الرصد الداخلي يبقى يعمل، وهو ما يغذّي خط التحقق أصلاً.

```
عملية واحدة للويب، عمليتان للتشغيل:

  ┌──────────────── تطبيق الويب (Next.js) ────────────────┐
  │  (site)  قشرة عامة   — مفهرسة، بلا جلسة إلزامية       │
  │  (app)   قشرة داخلية — رصد وتحليل، خلف تسجيل الدخول   │
  │  (admin) قشرة إدارية — مراجعة ونشر وإدارة             │
  └───────────────────────────────────────────────────────┘
                           │
        ┌──────────────────┴──────────────────┐
   PostgreSQL                              Redis
        │                                     │
        └──────── العامل الخلفي (worker) ──────┘
                  استخراج · جدولة · صيانة
```

القاعدة الحاكمة: **قشرة واحدة عامة وقشرتان مغلقتان في تطبيق واحد**، ولكل قشرة
تخطيط جذري مستقل وسياسة أرشفة مستقلة.

## 2. المصطلحات

تعارض التسمية بين المنتجين مصدر خطأ دائم، فيُحسم هنا مرة واحدة:

| المصطلح العربي | الاسم البرمجي | التعريف |
|---|---|---|
| مصدر | `Source` | جهة تحقق يُستخرج منها (تأكد، إيكاد، كشاف). يُمثَّل بسجل `Account` مرتبط بـ `Platform` |
| عنصر مستخرج | `ExtractedItem` | مخرج خام من Apify. يبدأ `PENDING`، **غير منشور بحال** |
| مادة تحقق | `FactCheck` | المادة المنشورة على سلام: عنوان وملخص وحكم ومصدر ورابط أصلي |
| حكم | `Verdict` | قيمة من قائمة ثابتة — لا نص عربي حر في القاعدة |
| دليل | `Evidence` | مصدر مسترجع يُسند إجابة التشات، وله معرّف ورابط ووقت استرجاع |
| دورة استخراج | `ExtractionRun` | تشغيل واحد لمصدر واحد، له حالة وإحصاءات |
| بصمة | `fingerprint` | SHA-256 على صيغة مطبّعة، لمنع التكرار |

> **تنبيه:** النموذج المسمى `Post` في المخطط الحالي يعني **العنصر المستخرج الخام**،
> لا المادة المنشورة. يُعاد تسميته إلى `ExtractedItem` وفق [`migration.md`](migration.md).

## 3. الأدوار والصلاحيات

### 3.1 الأدوار

| الدور | الرتبة | الوصف | وصول اللوحة |
|---|---|---|---|
| `OWNER` | 5 | مالك المنصة — كل شيء بما فيه الأسرار والأدوار | كامل |
| `ADMIN` | 4 | مدير النظام — المستخدمون والإعدادات | كامل عدا الأسرار |
| `MODERATOR` | 3 | مراجع ومحرّر — يراجع وينشر ويحرّر المواد | تشغيلي |
| `VIEWER` | 2 | موظف اطلاع داخلي — رصد وتصدير فقط | اطلاع |
| `USER` | 1 | **مستخدم عام مسجَّل** — الموقع العام والتشات | **لا وصول إطلاقاً** |

`MODERATOR` يحل محل `SUPERVISOR` اسماً بالرتبة نفسها. `USER` دور جديد كلياً،
لأن المنصة القائمة لم يكن لها جمهور أصلاً.

### 3.2 قاعدة أمنية حاكمة على `USER`

مصفوفة الصلاحيات الحالية تبني الأدوار **بالتراكم** ابتداءً من `VIEWER`.
دمج `USER` في هذا التراكم يمنحه صلاحيات الرصد الداخلي.

> **FR-AUTH-01 (إلزامي):** صلاحيات `USER` مجموعة **منفصلة تماماً** لا تشتق من
> `VIEWER` ولا من غيره، ولا تحوي أي صلاحية تبدأ بـ `admin.` أو `accounts.` أو
> `extraction.` أو `reports.` أو `audit.` أو `settings.`.

## 11. سير العمل

### 11.1 نظام الأحكام

| القيمة | العربية | صالحة للمادة المنشورة | صالحة كمخرج للنموذج |
|---|---|---|---|
| `TRUE` | صحيح | ✅ | ✅ |
| `FALSE` | غير صحيح | ✅ | ✅ |
| `MISLEADING` | مضلل | ✅ | ✅ |
| `UNVERIFIED` | غير مؤكد | ✅ | ✅ |
| `NOT_FOUND` | لم يُعثر عليه | ✅ | ✅ |
| `UNDER_REVIEW` | قيد التحقق | ✅ | ❌ **حالة تحريرية لا يصدرها النموذج** |

الثقة ثلاث درجات: `HIGH` / `MEDIUM` / `LOW`. **لا نِسَب مئوية** ما لم توجد منهجية
كمية مثبتة. و`NOT_FOUND` لا يعني أن الادعاء خاطئ — غياب الدليل ليس دليل غياب.

### 11.2 آلة حالات النشر

```
العنصر المستخرج (ExtractedItem)
  PENDING ──قبول──> APPROVED ──تحويل──> CONVERTED
     └────رفض────> REJECTED

مادة التحقق (FactCheck)
  DRAFT ──نشر (صلاحية مستقلة)──> PUBLISHED ──سحب──> ARCHIVED
    ▲                                │
    └──────── تعديل مع حفظ التاريخ ───┘
```

| الانتقال | الصلاحية | الأثر |
|---|---|---|
| `PENDING → APPROVED` | `items.review` | لا ظهور عام |
| `PENDING → REJECTED` | `items.review` | يُحفظ السبب |
| `APPROVED → CONVERTED` | `posts.manage` | تُنشأ مادة `DRAFT` |
| `DRAFT → PUBLISHED` | `posts.publish` | **أول ظهور عام** + تدقيق |
| `PUBLISHED → ARCHIVED` | `posts.publish` | يختفي عاماً، يبقى السجل |

### 11.4 رحلات المستخدم

**زائر غير مسجَّل:** الرئيسية ← تصفح آخر عمليات التحقق ← بحث وفلترة ← صفحة تفاصيل
← فتح المصدر الأصلي. عند محاولة استخدام التشات يُدعى إلى التسجيل مع بيان السبب.

**مستخدم مسجَّل:** تسجيل الدخول ← «تحقق من خبر» ← كتابة الادعاء ← مطالعة الحكم
والثقة والأدلة ← فتح المصادر ← تقييم الإجابة ← الرجوع إلى محادثاته السابقة.

**مراجع (`MODERATOR`):** اللوحة ← طابور المراجعة ← فتح عنصر ← مطالعة المصدر الأصلي
← قبول أو رفض مع سبب ← تحويل المقبول إلى مسودة ← تحرير العنوان والملخص والحكم
والتصنيف والأدلة ← نشر ← تأكيد.

**مالك (`OWNER`):** اللوحة ← مؤشرات التشغيل ← فحص دورة استخراج فاشلة ← تصحيح إعداد
المصدر أو Actor ← تشغيل يدوي ← متابعة سجل التدقيق.

## 12. معايير القبول

معايير قابلة للاختبار آلياً. لا تُعدّ أي مرحلة مكتملة قبل تحقق ما يخصها.

| المعرّف | المعيار | نوع الاختبار |
|---|---|---|
| `AC-01` | لا يظهر عنصر بحالة `PENDING` أو `REJECTED` في أي استجابة عامة بأي مسار | E2E + تكامل |
| `AC-02` | القبول وحده لا يُظهر المادة عاماً؛ الظهور يتطلب إجراء نشر مستقلاً | E2E |
| `AC-03` | استجابة نموذج تحوي رابطاً خارج قائمة الأدلة تُرفض ولا تُخزَّن ولا تُعرض | وحدة |
| `AC-04` | استجابة نموذج بحكم خارج التعداد أو بـ `UNDER_REVIEW` تُرفض | وحدة |
| `AC-05` | `USER` لا يصل إلى أي مسار إداري ولو بمعرفة الرابط — 403 لا إخفاء | تكامل |
| `AC-06` | مستخدم لا يقرأ محادثة غيره ولو بمعرفة المعرّف — 404/403 | تكامل |
| `AC-07` | لا يظهر `APIFY_TOKEN` ولا `OPENAI_API_KEY` في حزمة العميل — فحص آلي على أثر البناء | وحدة |
| `AC-08` | تطبيع البحث العربي: «إسرائيل/اسرائيل» و«الامارات/الإمارات» تعطي النتائج نفسها | وحدة |
| `AC-09` | تشغيل المستخرج مرتين على البيانات نفسها لا ينتج عناصر مكررة | تكامل |
| `AC-10` | عنصر خام فاسد يُتجاهل ويُحصى والدورة تكتمل | وحدة |
| `AC-11` | كل حكم يحمل لوناً ورمزاً ونصاً — يُفهم بلا لون | فحص وصولية |
| `AC-12` | الرئيسية وصفحة التفاصيل والتشات تعمل على عرض 360px بلا تمرير أفقي | E2E |
| `AC-13` | كل قائمة لها حالات: تحميل، فراغ، خطأ | مراجعة + E2E |
| `AC-14` | القشرة العامة مفهرسة، والقشرتان الأخريان `noindex` | تكامل |
| `AC-15` | تجاوز السقف اليومي للتشات يُعيد 429 برسالة عربية واضحة | تكامل |
| `AC-16` | `tsc --noEmit` بلا أخطاء | آلي |
